★ 2026-09-24（续）· AD 导出面板（对话框本身）4K 自适应缩放
────────────────────────────────────────────────────────
  现象（用户确认）：4K 屏上「小」的是 AD 里的导出对话框本身——表单几何
  写死 96-DPI 的 452x452（mainWin.dfm），高分屏上就是一小块。
  方案（dist/mainWin.js，**需重启 AD 生效**）：面板每次显示时（mainWinShow
  开头 panelApplyScale()）把整个表单按系数放大——几何（Left/Top/Width/

             查不到/查询失败回退 1.5）；

  · 遍历用 ComponentCount/Components[i] + ControlCount/Controls[j] 双通道
    （ScriptForms 不能按名字访问嵌套控件，两种暴露模型都能盖住）；
    缺几何属性的非可视件（TSaveDialog）自动跳过——注意纯 JS 读不到的
    属性返回 undefined 而不抛错，靠 isFinite 校验挡住 NaN 回写。
  · auto 模式插显示器即插即用：下次打开对话框按新主屏重新判定。
  校验：scratch/panel_scale_test.js 40 项全过（平面/层级两种 ownership

★ 2026-09-22 21:30 · 打印丝印：自动缩放，一层一页
────────────────────────────────────────────────────────
现象：点「丝印」打印，整块板子被切成几段 —— F、B 两层打出来 5 页，每页只有
板子的一条横带（用户截图：打印预览「总数：5 纸张」，板子在页与页的接缝处被
横向锯开）。

根因，一个数字就够：那段打印页样式对图片写死了 `max-height: 250mm`。
  · 竖版 A4 扣掉 10mm 页边距后可用高度 277mm —— 250mm 装得下，所以这行
    一直没暴露；
  · 横版 A4 可用高度只有 190mm —— 250mm 高出 60mm，图片底部溢出到下一页时
    浏览器是**切断**不是缩小，板子于是被锯成几段。
  一个固定的毫米值不可能同时对横竖两个方向都成立，这才是病根。

修法：给每层一个**与纸张等大的固定高度盒子**；图片自己再占一个**绝对毫米**
高度的盒子，在**宽、高两个方向**都被限制为该盒子的 100%，并追加
`object-fit: contain`（过大时等比缩进盒子，不裁切、不拉伸）。
  · 所有尺寸都是绝对毫米，**不依赖任何百分比高度** —— 打印时各浏览器对
    「从 flex 推导出的高度能不能当百分比基准」并不一致。第一版修法用了 flex，
    复核时判定这个不确定性不可接受，改成了现在这样；
  · 每页高 = A4 可用高 − 1mm。留 1mm：内容正好等于页高时可能因取整多吐
    一张空白页；
  · 图片盒高 = 页高 − 9mm，那 9mm 是给标题的（4mm 字号 / 1.4 行高 + 2mm
    下间距 ≈ 7.6mm）。printtest 会从生成的 CSS 里把这两个数读出来核对；
  · 层间 `page-break-after: always`，`.page:last-child` 恢复 `auto`，
    尾部不多出空白页；
  · `break-inside: avoid` 保证一层绝不被从中间切开。
结果：F、B 各一页，共 2 页；板子缩放到装得下为止（长边贴边）。

顺带两处小修：
  · 打印页补 `<meta charset="utf-8">`（之前没声明编码，板名含中文时 h3
    标题有变乱码的风险；板名本身画在图里，故只影响标题文字）。
  · `w.onload` 移到 `w.document.close()` **之前**注册，并先 `w.focus()`。
    close() 会把 load 事件排进队列，晚一步挂的处理器有丢事件的可能。

文件：`web/util.js`，只动 `printSilkscreen()` 一个函数 —— web/ 是导出时从
磁盘读取的，**重新导出一次 HTML 即生效，不用重启 AD**。

校验：新增 `.workbuddy/printtest.js` **38/38**（把 printSilkscreen 抠出来在
vm 里真跑，逐条检查它交给浏览器的分页 HTML）。并做了反向验证 —— 同一套断言
指向改动前的备份文件时有 **17 条失败**，其中正包括「不许出现 250mm」「不许对
图片用固定 mm 的 max-height」和「图片盒必须是绝对毫米而不是推导出的百分比」，
证明断言不是空转。

说明：这是**结构验证** —— 断言「图片盒不可能超出纸张」这个几何关系，而不是真的
执行了一次打印。本机无头浏览器不产出 PDF（`--print-to-pdf` 的几种参数组合都试过，
全是空输出），「模拟打印再数页码」走不通。请在浏览器里实际打开一次打印预览确认。

★★ 2026-09-22 晚 · 顺带修掉一个致命 bug：导出的页面此前整页是死的 ★★
────────────────────────────────────────────────────────
**症状**：用当前代码导出的 HTML，`<script>` 块**根本解析不了**
（`Unexpected token ')'`），BOM 表、画布、菜单全部不工作。

**原因**：`core/ibom.js` 的 `generateFile()` 用
`html.replace("///X///", 文件内容)` 填槽位。JS 里**替换串**中的 `$`
是特殊语法，`$&` 表示「整个匹配到的文本」。而 `web/pep.js` 第 43 行
（PEP v0.4.3 原版）有 `var ... ,Z=u.pointermap,$=window.MSPointerEvent&&...`
——那个 `$` 是个**变量**，紧接着的 `&&` 让它变成了 `$&`。
于是拼接 pep.js 时，`$&` 被展开成槽位标记 `///POINTER_EVENTS_POLYFILL///`，
`return ///...` 把该行余下内容变成注释，括号失衡，**整个 script 块报废**。

**定性**：这是**上游一直存在的老 bug，与汉化无关**。已用对照实验证明：
   A 当前文件 + 原样 replace  → 解析失败
   B 当前文件 + 函数式 replace → 通过
   C **汉化前的英文原版** + 原样 replace → **同样失败**

**修法（只改 web/，无需重建、无需重启 AD）**：
把 `pep.js` 里那个变量 `$` 改名为 `_msPointer`（声明 + 使用共 2 处），
并在文件头注释里写明原因、禁止改回。修后 `$` 只剩正则 `/auto$/`
那一个锚点，`$&` 归零。

**为什么不去改 core/ibom.js**：更彻底的修法是给它加 `spliceSlot()`
（把 payload 作为**函数**传给 replace，彻底关闭 `$` 特殊语法），
但那属于 bundle 源，要重跑 Initialize.bat 并重启 AD。

0.6 【重要修复】点「运行」弹「灾难性故障」——脚本里的尾逗号
    现象：从 AD 的"选择条目运行"里执行 mainWin.js 的 startWin，弹
          「Error / 灾难性故障」，窗口打不开，且**不提示行号**。

    真正原因：**Borland_Lang.js 里有 6 处尾逗号**（`,` 紧跟在 `}` 之前），
    dist/mainWin.js 里有 1 处。

    Altium 编译每个 .PrjScr 文档用的是 **ES3 时代的老 JScript 引擎**，它不
    接受对象/数组字面量的尾逗号——这是**硬性语法错误**。而 Altium 把脚本文档
    的语法错误一律报成「灾难性故障」，不给行号，所以看起来像窗体问题，
    实际是**解析问题**。

    最坑的一点：**Node 完全接受尾逗号**。所以 node --check 全绿、62 条断言
    全绿，而 Altium 根本打不开窗口。

    处理：
      · Borland_Lang.js 删掉 6 处尾逗号（LANG_DFM 末尾、LANG_UI 末尾、
        LANG_PACKS.zh.dfm 末尾、zh.ui 末尾、zh 对象末尾、LANG_PACKS 末尾）
      · dist/mainWin.js 删掉 langCaptions() 里 out.push({...}) 末尾那处
      · bundle 重建，2529003 → **2528997 bytes**（正好少 6 个字符）

    同时新增守卫，避免再犯：
      · .workbuddy/langtest.js 新增第 15 组 es3Problems()（+9 条断言）：
        用**括号栈 + 最后有效 token** 判断尾逗号，顺带查 let/const、箭头函数、
        模板字符串。注意不能用按行的正则——`ReadString("General", "Language",
        "en")` 末尾也有 `,` 和 `)`，但那个逗号分隔的是函数实参，不是字面量元素，
        按行判会误报。自测覆盖了同行/跨行/三层嵌套尾逗号、函数实参、字符串内
        逗号、行注释与块注释内逗号。

    给后续维护的一句话规则：**语法必须停在 ES3。不能有尾逗号、不能 let/const、
    不能箭头函数、不能模板字符串。** 允许 var、function、===/!==、try/catch、
    .indexOf()、JSON.parse/stringify、正则字面量。改完任何 .js 都要跑 langtest。

    【附】同一轮还修了 dist/mainWin.dfm 的属性缩进错位（4 个 TabSheet 的
    Caption 缩进 0 应为 6；写入锚点的脚本把缩进算成「object 缩进 - 2」，
    正确是 **+ 2**；另丢了 1 行 HelpType）。dfm 确实不合法、也确实该修，
    但它**不是**这次报错的原因——当时下结论太快了。相关工具：
    .workbuddy/repair_dfm.py（从干净兄弟版本还原，--check 只校验）、
    inject_lang.py（写盘前自校验）。当时把 dfm 开头的 UTF-8 BOM 当成"正常现象、
    量缩进前剥掉就行"——**这个判断是错的**：BOM 本身就是 AD 报
    "Invalid stream format" 的原因，见「五」第 9 条与「六」的 dfm 校验说明。

四、使用前的必做一步
────────────────────────────────────────────────────────
rootPath.js 里写的是打包机器上的绝对路径：

    var CURRENT_PATH = "C:\\Users\\administrator1\\Desktop\\work\\InteractiveHtmlBomForAD-0.3.17\\";

把本目录放到别的位置后，**先双击运行一次 Initialize.bat**，它会按当前位置重写
rootPath.js，并重新拼接生成 dist\InteractiveHtmlBomForAD.js。

然后按 README 的步骤：
    1. 运行一次 Initialize.bat
    2. 用 AD 打开 InteractiveHtmlBomForAD.PrjScr
    3. 打开 PCB 文件，Run Script... → 运行 main()

五、以后再改这个项目时的注意事项（重要，务必先读）
────────────────────────────────────────────────────────
1. AD 实际执行的是 dist\InteractiveHtmlBomForAD.js 和 dist\mainWin.js
   （.PrjScr 只注册了这两个脚本单元）。core/ 与 ecad/ 只是源码。

   Initialize.bat 第 8 行把它们拼接成 bundle：
       copy /b rootPath.js + modules-lite\json2.js + modules-lite\lz-string.js
             + core\config.js + core\newstroke_font.js
             + ecad\AD10.js + core\ibom.js + tools\inPcb.js
             → dist\InteractiveHtmlBomForAD.js

   所以：改了 core/ 或 ecad/ 之后，必须重建 bundle，并且重启 AD。
   典型症状：新列显示出来了，但每行都是空的。
   web/ 下的文件是运行时从磁盘读取的，改完立即生效，不需要重建。

2. core/ibom.js 的 generateBom() 与 dist/mainWin.js 的 pickBom() 是两份并行实现，
   任何一边变了，另一边必须跟着改，否则 CLI 入口和 GUI 入口行为不一致。

3. Altium 的 IPCB_Component **没有 Description 属性**。BOM 的 Description 列对应
   SourceDescription（GetState_SourceDescription），仅在 PCB 由原理图 Update
   同步过来时才有值。

4. 读取不存在的 COM 属性会返回 undefined 且**不抛异常**，try/catch 抓不到拼错的属性名。
   所以取值要多个候选依次探测、只接受非空结果。
   同理，AD 的 ComponentKind 既可能返回数字枚举也可能返回字符串，两种都要处理。

5. 画布层级：每个面是 bg(0) → fab(1) → slk(2) → hl(3) 四层叠加，高亮层永远最上。
   任何需要压在高亮之上的东西，必须画到 canvasdict.highlight 上。

6. populateBomTable() 会拆掉并重建 DOM，initDone === false 时不能被 noBomVisible()
   之类调用，必须先用 if (initDone) 保护。

7. 新增列时，表头（populateBomHeader）和表体（populateBomBody）必须同步改，
   且不能插在 numCol 或复选框列之前——复选框代码用 childNodes[n+1] 硬编码定位，
   插前面会错位。

10. 位号 / 参数标签（web/ 前端，与 AD 侧无关）：
   · 标签的位移和旋转都以**位号（ref）**为键，不能用元件下标 ——
     下标会随板子重新编辑 / 重新导出而变，旧存档就会错位。
   · 位移存 labelOffsets（板子毫米），旋转存 labelRotations（角度，90 的倍数）。
     两个表都是「ref → { ref/val → 值 }」，故意分开存，这样旧存档缺
     labelRotations 时按"未旋转"处理，不会连带把位移读坏。
   · 绘制时旋转要**绕标签自身锚点**转：先 `ctx.translate(0, row)` 把基线点移到
     局部原点，再 `ctx.rotate(extra)`。如果只加一个 rotate 而不先 translate，
     标签会绕封装中心公转，看起来像被甩出去。
   · 命中框要跟着转：labelHitScan() 靠 `rotated` 标志把宽高对调，所以那个标志
     必须是 `(m.ang + extra) % 180 !== 0` —— 忘了加 `extra` 就会出现
     "转完之后点不中 / 点到旁边的标签"。
   · 空格键只在**已选中标签**时才 preventDefault，否则会吃掉正常翻页和
     按钮的空格激活。焦点在文本框里时直接 return（与 "n" 键同一套判断）。
   · 改这些标签代码后跑 `.workbuddy/labeltest.js`（130 条）与
     `.workbuddy/pagetest.js`（33 条），两者都是纯 Node + vm，不依赖浏览器。
